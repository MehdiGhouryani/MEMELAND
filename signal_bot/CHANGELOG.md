# تاریخچه‌ی پروژه (خلاصه‌شده)

این فایل جایگزین همه‌ی `CHANGELOG_*.md`/`AUDIT_*.md` قدیمی + `MANIFEST.md`
شده — همون تاریخچه، خیلی خلاصه‌تر. برای جزئیات پیاده‌سازی، به خودِ کد
(کامنت‌های داخل فایل‌ها) مراجعه کن.

## فاز ۰ تا ۵ (تکامل اولیه‌ی بات، پیش از سایت)

- **فاز ۰:** بازسازی از یه اسکریپت تک‌فایلی ۱۵۷۷ خطی به ساختار ماژولار
  (config→db→services→handlers). سیستم نقش پنج‌سطحی (rookie/explorer/
  guardian/alpha/og).
- **فاز ۱:** ثبت سیگنال (Full Signal با عکس، Fast Call بدون آن)، بررسی
  دستی ادمین.
- **فاز ۲:** پرداخت NOWPayments برای Prize Pool، سیستم فصل/برنده.
- **فاز ۳:** Alpha Score (Wilson score lower bound) برای رتبه‌بندی منصفانه‌تر.
- **فاز ۴-۵:** سخت‌سازی وب‌هوک IPN، ممیزی preflight کامل.
- **پشتیبانی گروه:** `/fastcall`, `/fullsignal` قابل‌استفاده در گروه؛
  `chat_data` به‌جای `user_data` برای جلوگیری از نشتِ state بین چت‌ها.
- **باگ‌های اصلی فیکس‌شده تو این بازه:** ری‌استارت خودکار فصل، ناهماهنگی
  سطح بعد از پاداش streak/دستی، بلاک‌شدن دکمه‌ی جهت.

## سایت (Memeland Hub) — از Postgres/Supabase تا SQLite

قبل از این بخش، سایت یه HTML استاتیک بود که مستقیم به Supabase/Postgres
وصل می‌شد (RPCهای `signal_create`, `telegram_login`, و...)، و بات با یه
پل HTTP (`site_sync.py`) باهاش سینک می‌شد.

**فازهای اولیه‌ی سایت (رو Postgres، قبل از این نشست):**
فاز ۰ (قفل PIN/kv_store)، فاز ۱ (Telegram Login Widget + HMAC)، فاز ۲
(جدول relational برای سیگنال‌ها به‌جای بلاب مشترک)، فاز ۳ (پل آپلود عکس
به Supabase Storage)، فاز ۰-ب (`caller_ratings` relational — چون بلاب
قدیمی فقط admin/caller رو قبول می‌کرد، عضو معمولی نمی‌تونست رأی بده).

**این نشست — تبدیل به Telegram WebApp + مهاجرت کامل به SQLite:**

1. **آماده‌سازی WebApp:** بوت‌استرپ `Telegram.WebApp` (ready/expand/تم)،
   تبدیل هر ۹ محل `prompt()`/`confirm()` به مودال داخل‌صفحه یا `showConfirm`
   بومی (چون WebView تلگرام پشتیبانی تضمین‌شده نداره)، دکمه‌ی WebApp تو
   منوی بات.
2. **پیوت به SQLite:** به‌جای حدس‌زدن اسکیمای Postgres قدیمی، کل بک‌اند
   سایت از صفر رو SQLite بازسازی شد (`signal_bot/site/`: `db.py`,
   `auth.py`, `signals.py`, `ratings.py`, `kv.py`, `routes.py`). بات و
   سایت الان هم‌محل، یه پروسه، سرو از همون سرور aiohttp که قبلاً فقط IPN
   بود.
3. **بازنویسی کامل JS سایت:** هر `sb.rpc`/`sb.from` (۳۳+ نقطه) به
   `fetch('/site/...')` تبدیل شد. `site_sync.py` (بات→سایت) از HTTP call
   به فراخوانی مستقیم پایتونی عوض شد — امضای توابعش دست‌نخورده موند.
4. **فیچر channel واقعی:** ویزارد ثبت سیگنال بات یه قدم انتخاب کانال
   گرفت (قبلاً همه‌چی هاردکد `channel=alt` سینک می‌شد).
5. **بررسی منطقی فرآیندها:** اسم کالر الان از بات مستقیم پاس داده می‌شه
   (نه فقط وقتی کاربر جداگانه رو سایت لاگین کرده)؛ امتیازدهی کالر الان
   بر اساس `caller_telegram_id` (نه فقط اسم) match/update می‌شه تا تغییر
   اسم تلگرام باعث پخش‌شدن یا قاطی‌شدن امتیازها نشه.

### باگ‌های واقعی که تو همین مهاجرت پیدا و فیکس شدن
- `PicklePersistence` + `bot_data["ipn_runner"]` (آبجکت aiohttp غیر-قابل-pickle) → کرش سر استارت. رانر رفت رو یه attribute ساده.
- مسیر فایل HTML سایت (۲ `..` به‌جای ۳ تا) → `GET /` صد-چهار می‌داد.
- SQLite دو تا NULL رو رو UNIQUE constraint «برابر» حساب نمی‌کنه → upsert امتیازدهی عملاً کار نمی‌کرد.
- `entry_open` تو لیست فیلدهای مجاز ویرایش سیگنال نبود → فرم ویرایش ۴۰۰ می‌داد.
- باگ تاریخی caller/date تو bulk-import (فیلدها پارس می‌شدن ولی هیچ‌وقت فرستاده نمی‌شدن) — بالاخره واقعاً فیکس شد.
- `quickUpdateSignal`/`toggleEntryWindow` تو UI اصلاً admin-only نبودن (صاحبِ سیگنال هم باید دسترسی داشته باشه) — بک‌اند اولیه سخت‌گیرتر از UI واقعی بود.

## وضعیت فعلی
بات و سایت هم‌محل، SQLite مشترک برای signals/sessions/caller_ratings/محتوا.
فقط آپلود عکس هنوز رو Supabase Storage‌ه (عمداً دست‌نخورده، کار جداست).

## بازبینی UI/UX — فاز ۰ (متنی/چیدمانی، بدون تغییر دیتابیس)
بعد از یه دور تحلیل UX روی منوها/متن‌های نمایشی + تحقیق روی نمونه‌های
خارجی (گایدلاین Telegram Mini App، اصول گیمیفیکیشن/لیدربورد، اپ‌های
پرتفوی کریپتو)، این ۴ مورد پیاده و با اجرای واقعی تست شدن:

1. **جابجایی «ثبت سیگنال»:** از اولین/برجسته‌ترین دکمه‌ی منوی اصلی به
   ردیف پایین‌تر منتقل شد (`main_menu_kb`) — چون این دکمه برای همه نشون
   داده می‌شه، نه فقط کسی که می‌خواد سیگنال بده؛ اولین برخورد کاربر با
   منو باید «مصرف سیگنال» باشه.
2. **رفع تداخل واژه‌ی «رول»:** برچسب نمایشی رول پیشرفتی کاربر
   (rookie→og) از «رول» به «درجه» تغییر کرد — چون هم با «سطح» (LEVELS
   بر اساس امتیاز) و هم با مفهوم رول سایت (admin/caller/...) قاطی
   می‌شد. «رول مدیریتی» (Admin/VIP Helper) دست‌نخورده موند، چون مفهوم
   واقعاً جداییه. اعمال شد تو: `common.py`, `texts.py`, `signals.py`,
   `admin.py`, `keyboards.py`.
3. **یکسان‌سازی آیکون 🏆:** تب «نتایج» سایت (که سیگنال‌ها/نتایج رو
   نشون می‌ده) از 🏆 به ✅ تغییر کرد تا با 🏆 لیدربورد بات/سایت (که
   رتبه‌بندی کاربرهاست، نه نتیجه‌ی سیگنال) اشتباه گرفته نشه.
4. **نمایش قانون امتیازدهی تو لحظه‌ی تصمیم:** صفحه‌ی انتخاب نوع سیگنال
   (`menu_signal`) الان درجه‌ی کاربر، وضعیت تأیید خودکار/دستی، و سقف
   امروز (استفاده‌شده/باقی‌مونده) رو مستقیم نشون می‌ده — قبلاً این
   اطلاعات فقط تو `/help` بود.

بقیه‌ی موارد بازبینی (یکی‌کردن لیدربورد/تابلوی افتخار/پاداش‌ها، لیدربورد
نسبی، کارت‌محورسازی پروفایل، تم داینامیک Mini App و...) برای فازهای
۱ تا ۳ برنامه‌ریزی شدن — هنوز پیاده نشدن.

## بازبینی UI/UX — فاز ۱ (بازآرایی منو، بدون تغییر schema دیتابیس)
1. **هاب مشترک رتبه‌بندی/جوایز:** «لیدربورد»، «تابلوی افتخار» و
   «پاداش‌های من» که قبلاً سه ردیف جدا و غیرمجاور تو منوی اصلی بودن،
   الان زیر یه کیبورد مشترک تب‌دار جمع شدن (`ranking_hub_kb` در
   `keyboards.py`) — از هرکدوم مستقیم می‌شه به بقیه رفت. callback_data
   هرکدوم دست‌نخورده مونده (menu_leader/menu_halloffame/menu_myrewards/
   menu_prize)، پس routing تو `main.py` تغییر نکرد؛ فقط `profile.py` و
   `payments.py` به‌جای `back_main_kb`/`leader_kb` جدا، همین کیبورد
   مشترک رو برمی‌گردونن. منوی اصلی هم یه ردیف کمتر شد (تابلوی افتخار/
   پاداش‌ها حذف شدن، چون الان زیر همون دکمه‌ی «🏆 رتبه‌بندی و جوایز»ان).
2. **رفع تناقض دسترسی به استخر جایزه:** «💎 استخر جایزه» قبلاً فقط تو
   `caller_menu_kb` بود (فقط کسی که سیگنال داده می‌دیدش)، درحالی‌که
   برنده‌های همون استخر تو «تابلوی افتخار» برای همه نمایش داده می‌شد —
   و «🤝 حمایت از ما» (که برای همه بازه) مستقیم به همون جدول
   `prize_pool` واریز می‌کنه. الان «استخر جایزه» به‌عنوان تب چهارم هاب
   بالا برای همه در دسترسه؛ میان‌بر قبلی‌اش تو `caller_menu_kb` هم
   دست‌نخورده موند.

هر دو مورد با اجرای واقعی هندلرها (بدون شبکه، با mock سطح `ExtBot`) و
یه بوت رگرسیون کامل بات+سایت تست شدن.

## بازبینی UI/UX — فاز ۲ (کوئری جدید DB — لیدربورد نسبی + کارت‌محورسازی پروفایل)
1. **لیدربورد نسبی:** کوئری جدید `get_leaderboard_ranked_full` (همون
   لیدربورد دوره‌ای قبلی، ولی بدون LIMIT + ستون `RANK() OVER`) اضافه شد.
   `leaderboard_text` الان اگه کاربر تو تاپ ۱۰ نمایش‌داده‌شده نباشه، یه
   بخش «📍 موقعیت تو» جدا نشون می‌ده (۲ نفر بالا + خودش + ۲ نفر پایین)،
   به‌جای اینکه کاربرهای رتبه‌ی پایین‌تر هیچ بازخوردی از لیدربورد نگیرن.
   اگه کاربر اصلاً تو اون دوره سیگنالی نداشته باشه، پیام راهنما نشون
   داده می‌شه («این دوره هنوز تو لیدربورد نیستی»).
2. **کارت‌محورسازی پروفایل:** `menu_stats`/`menu_profile` الان
   `profile_headline_text` (فقط درجه/سطح/پیشرفت/امتیاز کل/رتبه کلی —
   ۴ تای کلیدی) رو با دکمه‌ی «🔍 جزئیات بیشتر» نشون می‌ده؛ نسخه‌ی کامل
   قبلی (۱۴ آیتم) به `menu_profile_details` منتقل شد، عین قبل.

تست شد: با ۱۵ کاربر واقعی تو DB (برای شبیه‌سازی رتبه‌ی بیرون از تاپ ۱۰)،
هم برای کاربر تو تاپ ۱۰ (نباید تکراری نشون بده)، هم کاربر بدون سیگنال
این دوره، هم نسخه‌ی خلاصه/کامل پروفایل — همه با اجرای واقعی هندلر و کوئری
واقعی رو SQLite، نه فرض.

## بازبینی UI — فاز ۳ (پالیش Mini App سمت سایت، رنگ‌بندی استاندارد)
1. **تم روشن/تاریک داینامیک:** `:root`/`[data-theme="dark"]` و
   `[data-theme="light"]` جدا شدن. هیوهای برند (تیل/صورتی/طلایی/قرمز)
   تو هر دو حالت حفظ شدن، ولی نسخه‌ی روشن عمیق‌تر شدن تا رو پس‌زمینه‌ی
   سفید کنتراست AA داشته باشن (نسخه‌ی رنگ‌پریده‌ی قبلی رو سفید عملاً
   ناخوانا بود). `applyTelegramTheme()` بر اساس `tg.colorScheme` ست
   می‌شه و با رویداد `themeChanged` زنده آپدیت می‌شه؛ پس‌زمینه‌ی هاردکد
   همیشه-تاریک (`setBackgroundColor('#080a10')`) حذف شد. یه توکن جدید
   `--tint` هم اضافه شد چون چندجا `rgba(255,255,255,...)` هاردکد برای
   حالت‌های on/active بود که رو تم روشن دیده نمی‌شد.
2. **Skeleton loading:** ۴ کانتینر اصلی (خانه/نتایج/فعال/لیدربورد) که
   موقع بوت از API دیتا می‌گیرن، الان به‌جای خالی‌موندن، کارت‌های
   shimmer نشون می‌دن تا دیتای واقعی برسه (رفتار innerHTML-overwrite
   توابع render دست‌نخورده موند). `prefers-reduced-motion` هم رعایت شد.
3. **BackButton بومی:** `tg.BackButton` الان خارج از تب «خانه» نشون داده
   می‌شه و دقیقاً هم‌ارز تپ‌کردن «🏠 خانه»ست.
4. **Haptic feedback:** یه هلپر واحد (`haptic()`) اضافه شد و رو تعویض
   هر ۷ تب/فیلتر اصلی (`select`) + موفقیت/خطای هر ۵ فلوی PIN (ورود
   ادمین/کالر/اشتراک/کد پیشرفته) وصل شد.

**ناقص/باقی‌مونده از فاز ۳:** جایگزینی دکمه‌های فرم اصلی (ثبت/ویرایش
سیگنال) با `MainButton` بومی تلگرام انجام نشد — چون نیازمند بازآرایی
ساختار مودال‌هاست و ریسک بیشتری داره؛ برای یه فاز جدا (اگه لازم شد)
گذاشته شد.

همه‌ی موارد با `node --check` (اعتبارسنجی واقعی سینتکس JS استخراج‌شده)
+ یه بوت زنده‌ی سرور که HTML واقعی سرو‌شده رو برای حضور هر ویژگی چک کرد،
تأیید شدن.

## بازبینی UI/UX — دور دوم (فاز ۴) — فازبندی
بعد از یه دور بازبینی دیگه (تمرکز رو گرافیک SVG، رنگ‌بندی، و استانداردهای
UX)، ۴ زیرفاز برنامه‌ریزی شد، به ترتیب ریسک/وابستگی:
1. جایگزینی alert() خام مرورگر با پاپ‌آپ بومی تلگرام — ✅ انجام شد
2. دسترسی‌پذیری (focus states + اندازه‌ی دکمه‌های کوچک) — در انتظار
3. تفکیک رنگی گرادیان اکشن عادی از VIP + رنگ رتبه‌ی لیدربورد کالرها — در انتظار
4. SVG گرافیکی مینیمال (لوگو هیرو، empty state، قفل VIP، بج رتبه) — در انتظار

### زیرفاز ۱ — جایگزینی alert() (انجام‌شده)
تابع `notify(message)` اضافه شد: اگه تو تلگرام باز شده باشه از
`tg.showAlert()` بومی استفاده می‌کنه، وگرنه (تست خارج از تلگرام) به
`alert()` معمولی fallback می‌کنه. هر ۵۴ محل `alert(...)` قبلی (بجز
تأییدها که قبلاً `tg.showConfirm` بودن) به `notify(...)` تبدیل شدن.
تست شد: `node --check` روی JS استخراج‌شده + بوت زنده‌ی سرور با چک صریح
تعداد فراخوانی‌ها و باقی‌موندن دقیقاً یه `alert(` (همون fallback داخلی).

### زیرفاز ۲ — دسترسی‌پذیری (انجام‌شده)
- استایل `:focus-visible` سراسری (outline تیل‌رنگ) برای دکمه/تب/چیپ/ورودی
  اضافه شد — قبلاً هیچ نشونه‌ی بصری فوکوس برای پیمایش کیبوردی/تلگرام
  دسکتاپ وجود نداشت.
- اندازه‌ی لمسی `.mini-btn`, `.ba-btn`, `.admin-btn`, `.filter-chip` از
  حدود ۲۵px به حداقل ۳۲-۳۴px ارتفاع رسوند (هنوز کامل ۴۴px استاندارد
  نیست، ولی تعادل بین تراکم دیتای معاملاتی و قابل‌لمس‌بودن).
تست شد با `node --check` + بوت زنده‌ی سرور و چک صریح حضور هر قانون CSS.
