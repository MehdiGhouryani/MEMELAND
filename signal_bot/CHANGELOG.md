# تاریخچه‌ی پروژه (خلاصه‌شده)

این فایل جایگزین همه‌ی `CHANGELOG_*.md`/`AUDIT_*.md` قدیمی + `MANIFEST.md`
شده — همون تاریخچه، خیلی خلاصه‌تر. برای جزئیات پیاده‌سازی، به خودِ کد
(کامنت‌های داخل فایل‌ها) مراجعه کن.

## فاز ۰ تا ۵ (تکامل اولیه‌ی بات، پیش از سایت)

- **فاز ۰:** بازسازی از یه اسکریپت تک‌فایلی ۱۵۷۷ خطی به ساختار ماژولار
  (config→db→services→handlers). سیستم نقش پنج‌سطحی (rookie/explorer/
  guardian/alpha/og).
- **فاز ۱:** ثبت سیگنال (Full Signal با عکس، Fast Call بدون آن)، بررسی
  دستی ادمین.
- **فاز ۲:** پرداخت NOWPayments برای Prize Pool، سیستم فصل/برنده.
- **فاز ۳:** Alpha Score (Wilson score lower bound) برای رتبه‌بندی منصفانه‌تر.
- **فاز ۴-۵:** سخت‌سازی وب‌هوک IPN، ممیزی preflight کامل.
- **پشتیبانی گروه:** `/fastcall`, `/fullsignal` قابل‌استفاده در گروه؛
  `chat_data` به‌جای `user_data` برای جلوگیری از نشتِ state بین چت‌ها.
- **باگ‌های اصلی فیکس‌شده تو این بازه:** ری‌استارت خودکار فصل، ناهماهنگی
  سطح بعد از پاداش streak/دستی، بلاک‌شدن دکمه‌ی جهت.

## سایت (Memeland Hub) — از Postgres/Supabase تا SQLite

قبل از این بخش، سایت یه HTML استاتیک بود که مستقیم به Supabase/Postgres
وصل می‌شد (RPCهای `signal_create`, `telegram_login`, و...)، و بات با یه
پل HTTP (`site_sync.py`) باهاش سینک می‌شد.

**فازهای اولیه‌ی سایت (رو Postgres، قبل از این نشست):**
فاز ۰ (قفل PIN/kv_store)، فاز ۱ (Telegram Login Widget + HMAC)، فاز ۲
(جدول relational برای سیگنال‌ها به‌جای بلاب مشترک)، فاز ۳ (پل آپلود عکس
به Supabase Storage)، فاز ۰-ب (`caller_ratings` relational — چون بلاب
قدیمی فقط admin/caller رو قبول می‌کرد، عضو معمولی نمی‌تونست رأی بده).

**این نشست — تبدیل به Telegram WebApp + مهاجرت کامل به SQLite:**

1. **آماده‌سازی WebApp:** بوت‌استرپ `Telegram.WebApp` (ready/expand/تم)،
   تبدیل هر ۹ محل `prompt()`/`confirm()` به مودال داخل‌صفحه یا `showConfirm`
   بومی (چون WebView تلگرام پشتیبانی تضمین‌شده نداره)، دکمه‌ی WebApp تو
   منوی بات.
2. **پیوت به SQLite:** به‌جای حدس‌زدن اسکیمای Postgres قدیمی، کل بک‌اند
   سایت از صفر رو SQLite بازسازی شد (`signal_bot/site/`: `db.py`,
   `auth.py`, `signals.py`, `ratings.py`, `kv.py`, `routes.py`). بات و
   سایت الان هم‌محل، یه پروسه، سرو از همون سرور aiohttp که قبلاً فقط IPN
   بود.
3. **بازنویسی کامل JS سایت:** هر `sb.rpc`/`sb.from` (۳۳+ نقطه) به
   `fetch('/site/...')` تبدیل شد. `site_sync.py` (بات→سایت) از HTTP call
   به فراخوانی مستقیم پایتونی عوض شد — امضای توابعش دست‌نخورده موند.
4. **فیچر channel واقعی:** ویزارد ثبت سیگنال بات یه قدم انتخاب کانال
   گرفت (قبلاً همه‌چی هاردکد `channel=alt` سینک می‌شد).
5. **بررسی منطقی فرآیندها:** اسم کالر الان از بات مستقیم پاس داده می‌شه
   (نه فقط وقتی کاربر جداگانه رو سایت لاگین کرده)؛ امتیازدهی کالر الان
   بر اساس `caller_telegram_id` (نه فقط اسم) match/update می‌شه تا تغییر
   اسم تلگرام باعث پخش‌شدن یا قاطی‌شدن امتیازها نشه.

### باگ‌های واقعی که تو همین مهاجرت پیدا و فیکس شدن
- `PicklePersistence` + `bot_data["ipn_runner"]` (آبجکت aiohttp غیر-قابل-pickle) → کرش سر استارت. رانر رفت رو یه attribute ساده.
- مسیر فایل HTML سایت (۲ `..` به‌جای ۳ تا) → `GET /` صد-چهار می‌داد.
- SQLite دو تا NULL رو رو UNIQUE constraint «برابر» حساب نمی‌کنه → upsert امتیازدهی عملاً کار نمی‌کرد.
- `entry_open` تو لیست فیلدهای مجاز ویرایش سیگنال نبود → فرم ویرایش ۴۰۰ می‌داد.
- باگ تاریخی caller/date تو bulk-import (فیلدها پارس می‌شدن ولی هیچ‌وقت فرستاده نمی‌شدن) — بالاخره واقعاً فیکس شد.
- `quickUpdateSignal`/`toggleEntryWindow` تو UI اصلاً admin-only نبودن (صاحبِ سیگنال هم باید دسترسی داشته باشه) — بک‌اند اولیه سخت‌گیرتر از UI واقعی بود.
